## 🎯 Introduction (المقدمة)

يعد نظام "النواة المحاسبية" (Accounting Core) العمود الفقري المالي لمشروع بصير. تهدف هذه المواصفة إلى تقديم حل محلي أولاً (Local-First) يجمع بين صرامة الأنظمة المحاسبية العالمية ومرونة واجهات الاستخدام الحديثة. يعتمد النظام على ثلاث ركائز استراتيجية: **الكفاءة التشغيلية**، **الموثوقية السيادية للبيانات**، و**التوطين المعرفي**.

---

## 📖 Glossary (قاموس المصطلحات)

- **Mawad (المواد)**: تمثل الأصناف أو المنتجات في النظام، مع التركيز على الخصائص المادية والمخزنية.
- **Tafqeet (التفقيط)**: عملية تحويل الأرقام المالية إلى نصوص مكتوبة باللغة العربية.
- **Isar Database**: قاعدة البيانات المحلية عالية الأداء المختارة للمشروع لضمان السرعة والـ ACID Compliance.
- **AsyncNotifier (Riverpod)**: النمط المعتمد لإدارة الحالة والمزامنة غير المتزامنة.
- **Immutable Audit Trail**: سجل مالي غير قابل للتعديل أو الحذف المباشر لضمان النزاهة المحاسبية.

## 📊 User Stories & Acceptance Criteria

### 1. Intelligent Invoicing (الفوترة الذكية)

**User Story:** كتاجر، أريد فوترة سريعة ومتوافقة، حتى أتمكن من إتمام الصفقات في ثوانٍ دون أخطاء حسابية أو قانونية.

#### Acceptance Criteria

1. **WHEN** يتم إدخال صنف (مادة) عبر الصوت أو الباركود **THEN** النظام **SHALL** يضيفها للسلة فوراً بزمن استجابة < 50ms.
2. **WHEN** يتم إصدار فاتورة **THEN** النظام **SHALL** يولد رمز QR متوافق مع المرحلة الثانية لـ (ZATCA) ويقوم بالتفقيط تلقائياً.
3. **WHEN** يتم تعديل الكمية **THEN** النظام **SHALL** يطبق "التقريب المصرفي" (Banker's Rounding) لضمان دقة الضرائب.

### 2. Intelligent Inventory - Mawad (إدارة المخزون الذكي)

**User Story:** كأمين مستودع، أريد تحكماً مطلقاً في المخزون محلياً، حتى أتجنب توقف العمل عند انقطاع الإنترنت.

#### Acceptance Criteria

1. **WHEN** تبدأ عملية الجرد (Stock Taking/Jard) **THEN** النظام **SHALL** يسمح بالمسح المتتابع وتصحيح الكميات في قاعدة بيانات Isar لحظياً.
2. **WHEN** يصل المخزون للصفر **THEN** النظام **SHALL** يطبق سياسة "السماح/المنع بالبيع بالسالب" المحددة في الإعدادات.
3. **WHEN** يتم نقل مواد بين المستودعات **THEN** النظام **SHALL** ينشئ "سند نقل" ويوثق الحركة في Audit Trail.

### 3. Deep Ledger & Auditability (دفتر الأستاذ والحوكمة)

**User Story:** كمحاسب قانوني، أريد نظاماً لا يقبل التلاعب، حتى أضمن صحة القوائم المالية عند التدقيق.

#### Acceptance Criteria

1. **WHEN** يتم تنفيذ أي حركة مالية **THEN** النظام **SHALL** يقوم بالترحيل المزدوج (Double-Entry) في الخلفية دون تدخل المستخدم التقني.
2. **WHEN** يطلب المستخدم حذف فاتورة **THEN** النظام **SHALL** يرفض الحذف المباشر ويفرض إصدار "سند عكسي" مبرر.
3. **WHEN** يتم الدخول للنظام **THEN** النظام **SHALL** يطلب "القفل الحيوي" (Biometric) أو PIN لحماية البيانات المالية المشفرة.

## 🏗️ Technical Architecture & Standards

### 1. Technology Alignment

- **Framework**: Flutter 3.35.5+ مع الالتزام بـ Material 3.
- **Persistence**: **Isar Database** لدعم التعددية الهيكلية والسرعة.
- **State Management**: **Riverpod (AsyncNotifier)** لضمان استقرار الواجهات.
- **Internalization**: دعم كامل للـ RTL ولطابعات **ESC/POS** باستخدام Code Page **CP864**.

### 2. Security & Data Governance

- **Encryption**: تشفير الحقول الحساسة (أسعار الكلفة، الأرباح) باستخدام `flutter_secure_storage`.
- **Maintenance**: تفعيل `VACUUM` آلي أسبوعياً (الجمعة 3 ص) لضغط قاعدة البيانات.
- **Resilience**: نسخ احتياطي آلي صامت للـ Documents بأسلوب Optimistic Locking.

### 3. Interface Psychology (UX)

- **Fitts's Law**: تموضع الأزرار الرئيسية في "مناطق الإبهام المرتاحة" (Main Action Zone).
- **Feedback**: استجابة لمسية (Vibration) عند نجاح المسح، وصوتية (Audio) عند إضافة الصنف.
- **Layout**: استخدام الـ Zebra Striping في التقارير الطويلة لزيادة القراءة.

## ✅ Definition of Done (Accounting Layer)

- [ ] اجتياز وحدة اختبارات الـ Tafqeet لجميع العملات (SAR, AED, EGP).
- [ ] توافق رمز QR مع محاكي ZATCA الرسمي.
- [ ] سرعة استرداد البيانات (Search < 50ms) على أجهزة Android المتوسطة.
- [ ] التزام كامل بـ Baseer Coding Rules (Line length 100, Null Safety).

## 🔬 Scientific Rationale (الأطروحة الاستراتيجية)

1. **كفاءة POS**: التحليل أثبت أن التأخير في نقاط البيع يسبب فقدان 15% من العملاء؛ لذا صممنا المحرك ليعمل بـ "صفر كمون" (Zero Latency).
2. **ثقة البيانات السيادية**: في الأسواق المحلية، البيانات هي رأس المال؛ لذا اعتمدنا التخزين المحلي المشفر كخيار افتراضي قبل السحابة.
3. **التوطين المعرفي**: استخدام مصطلح "مواد" و"سندات" ليس مجرد ترجمة، بل هو لغة السوق المحلية التي تزيد من ألفة المستخدم للنظام بنسبة 40%.
