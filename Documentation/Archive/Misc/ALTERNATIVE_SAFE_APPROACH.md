# النهج البديل الآمن - بدون تغيير يدوي

**التاريخ:** 1 ديسمبر 2025  
**الحالة:** ✅ جاهز للتنفيذ الفوري

---

## 🎯 الحل البديل الأفضل

### لماذا نهج بديل؟

**المشكلة:**

- تغيير الفرع الافتراضي على GitHub يتطلب خطوة يدوية
- قد يكون مربكاً للمستخدم

**الحل:**

- **لا نحذف main من GitHub!**
- نبقي كلا الفرعين مؤقتاً
- نجعل master هو الفرع النشط للتطوير
- نحذف main لاحقاً عندما نكون جاهزين

---

## ✅ الخطوات الآمنة (لا تحتاج تغيير يدوي!)

### الخطوة 1: تنظيف المراجع المحلية

```bash
git remote prune origin
git fetch --all --prune
```

**ما يفعله:**

- ينظف المراجع القديمة
- يحدث قائمة الفروع

### الخطوة 2: التأكد من أننا على master

```bash
git checkout master
git pull origin master
```

**ما يفعله:**

- يتأكد أننا على الفرع الصحيح
- يحدث master

### الخطوة 3: إضافة ملاحظة في README

```bash
# إضافة ملاحظة للمطورين الجدد
echo "⚠️ **ملاحظة:** الفرع النشط للتطوير هو \`master\` وليس \`main\`" >> README.md
git add README.md
git commit -m "docs: add note about active development branch"
git push origin master
```

**ما يفعله:**

- يوضح للجميع أن master هو الفرع النشط
- يمنع الارتباك

## 🎯 الحالة النهائية

### بعد هذه الخطوات:

```
الفروع على GitHub:
├─ main (قديم، غير نشط) ⚠️
├─ master (نشط، للتطوير) ✅
└─ backup-main-final (نسخة احتياطية) 💾
```

**الفوائد:**

- ✅ لا حاجة لتغيير يدوي
- ✅ لا مخاطر
- ✅ يمكن حذف main لاحقاً
- ✅ master هو الفرع النشط

---

## 📋 الخطوات الإضافية (اختيارية)

### إذا أردت حذف main لاحقاً:

**الطريقة 1: عبر GitHub UI (سهل)**

1. اذهب إلى: https://github.com/mohammed-murad-alqabal/Basser_MVP/branches
2. ابحث عن فرع `main`
3. اضغط على أيقونة 🗑️ (سلة المهملات)
4. أكد الحذف

**الطريقة 2: عبر Git (متقدم)**

```bash
# فقط إذا كنت متأكداً 100%
git push origin --delete main
```

## ✅ ما لا تحتاجه

### لا حاجة لـ:

- ❌ تغيير الفرع الافتراضي على GitHub
