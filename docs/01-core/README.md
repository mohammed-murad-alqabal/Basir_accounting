# Basir Accounting — نظام بصير المحاسبي

> **حالة المشروع:** تطوير نشط؛ تحدد حالة كل ادعاء عملي أو اختباري أو تنظيمي بواسطة الدليل المرتبط بـSHA.
> **مصدر الحالة التنفيذية:** الكود والاختبارات ونتائج التكامل المستمر عند لقطة محددة.
> **خارطة العمل الحالية:** [خطة تنفيذ بصير](docs/Strategic/خطة_تنفيذ_بصير.md).
> **حوكمة الوثائق:** [نموذج السلطة](docs/00-governance/AUTHORITY_MODEL.md).

Basir Accounting هو تطبيق محاسبي عربي أولًا مبني باستخدام Flutter وDart، مع مكونات Rust لعمليات محاسبية وتكاملية محددة. يركز المشروع على تسجيل المعاملات، وإدارة دليل الحسابات، والفواتير، والمخزون، والتقارير، وتجربة استخدام RTL، ضمن مسار تطوير منضبط بالمواصفات والاختبارات.

## نطاق النظام

| المجال | النطاق المقصود | الحالة الصحيحة للاستخدام |
|---|---|---|
| الدفتر العام | قيود يومية، دليل حسابات، فترات مالية، وتقارير أساسية. | راجع المتطلبات والاختبارات المرتبطة قبل اعتماد أي سلوك. |
| الفوترة وVAT | مستندات بيع وشراء وحساب ضريبة وسير ترحيل. | القدرات تختلف حسب المسار؛ لا يفترض الاكتمال من هذا الجدول. |
| ZATCA | XML/UBL وQR وتدفقات تكاملية قيد التطوير والاختبار. | **محاكاة/تحقق تقني جزئي؛ ليست شهادة امتثال إنتاجي.** |
| المخزون والتقارير | أصناف وحركات وتقارير وتحليلات. | تنفذ على مراحل وفق خارطة التنفيذ. |
| الأمن والحوكمة | أذونات وسجل تدقيق وتخزين آمن وضوابط CI. | لا يعلن مستوى أمان أو معيارًا إلا بدليل مؤرخ. |

## الحالة وكيفية التحقق

لا تستخدم badges ثابتة أو أعداد اختبارات غير مؤرخة لاتخاذ قرار تشغيل أو امتثال. استخدم الملفات التالية، وكلها تشرح حدود أدلتها:

| السؤال | المصدر الحاكم |
|---|---|
| ما الذي يعمل في هذه اللقطة؟ | الكود والاختبارات ونتائج CI المرتبطة بـSHA. |
| ما الذي يجب بناؤه؟ | متطلبات معتمدة ذات `REQ-*` ومعيار قبول. |
| ما الذي يجري تنفيذه الآن؟ | [خارطة التنفيذ](docs/Strategic/خطة_تنفيذ_بصير.md). |
| ما حالة حوكمة المعرفة ودين التوثيق؟ | [تقرير BKIP](docs/audits/bkip-2026-08/KNOWLEDGE_INTEGRITY_REPORT.md). |
| ما الأدلة المتاحة لنتائج CI؟ | [سجل أدلة CI](docs/audits/bkip-2026-08/appendices/CI_EVIDENCE.md). |
| ما نطاق ZATCA وما الذي بقي غير متحقق؟ | [سجل متطلبات الامتثال](docs/02-domain/requirements/COMPLIANCE_REQUIREMENTS.md). |

> **مهم:** لا يساوي وجود XML أو QR أو مسار Rust إثبات اتصال إنتاجي أو اعتماد تنظيمي. لا يستخدم لفظ **متوافق** إلا داخل سجل أدلة يحدد البيئة والاختبار والمالك وSHA.

## البنية التقنية

```text
lib/                    Flutter/Dart application
├── core/               خدمات ومزودات وtheme ونماذج مشتركة
├── features/           وحدات نطاقية، مثل accounting وinvoices وinventory
├── shared/             مكونات واجهة مشتركة
└── src/rust/           واجهات الربط مع Rust

rust/                   Rust workspace ومكونات المحرك والترحيلات
├── crates/             accounting_core, accounting_data, accounting_zatca وغيرها
└── migrations/         ترحيلات PostgreSQL/SQLx

test/ وintegration_test/  اختبارات Dart
.github/workflows/       بوابات CI والجودة والأمن والتوثيق
```

توضح [وثائق الحوكمة](docs/00-governance/README.md) أي طبقة تحسم السلوك أو النية أو الدليل عند وجود تعارض.

## البدء المحلي

تتحدد نسخ SDK والتبعيات من [`pubspec.yaml`](pubspec.yaml) وملفات Rust ضمن المستودع. بعد تثبيت الأدوات المطابقة للقيود الموجودة فيه:

```bash
flutter pub get
flutter analyze
flutter test
```

تختلف أوامر Rust بحسب المكون المستهدف. راجع `rust/Cargo.toml` وملفات workflow قبل تشغيل أي مهمة توليد أو ترحيل أو تكامل.
