# Runbook للتحقق من Snapshot موجة الإعدادات

## الغرض

يوفر `DriftSettingsSnapshotRunner` و`tool/run_drift_settings_snapshot.dart` مسارًا offline لتشغيل importer وparity على ملف JSON معقم ومراجع. لا يفتح هذا المسار قاعدة Isar التشغيلية، ولا يقرأ ملفات التطبيق تلقائيًا، ولا يفعّل Providers أو shadow-read.

## متطلبات اللقطة

يجب أن تحتوي اللقطة على `sanitized: true` و`schemaVersion: 1` ومصفوفتي `profiles` و`businessSettings`. ينبغي أن تكون كل هوية مستخدم وقيمة تعريفية pseudonymized قبل إدخال الملف إلى أي بيئة مشاركة. لا يثبت parser وحده أن الإخفاء كافٍ؛ تقع مراجعة الخصوصية على منشئ اللقطة.

| القاعدة | التطبيق |
|---|---|
| المصدر | نسخة مراجعة من Isar، لا قاعدة التشغيل مباشرة |
| الهوية | `userId` pseudonymous ولا يحمل قيمة الحساب الأصلية |
| الحقول | تُحافظ على القيم اللازمة للمقارنة، مع إزالة الأسرار والرموز والبيانات غير اللازمة |
| الإخراج | counts وmatch status فقط؛ لا payload أو userId أو fingerprints |
| التخزين | SQLite في الذاكرة ويُغلق بعد التقرير |

## التشغيل

بعد وضع لقطة مراجعة محليًا في ملف، يُشغّل الأمر التالي من جذر المشروع:

```bash
dart run tool/run_drift_settings_snapshot.dart /path/to/sanitized-settings.json
```

يخرج الأمر JSON تشخيصيًا يتضمن `clean`، counts الخاصة بالاستيراد، وحالة parity لكل شريحة، وعدد النطاقات الغامضة. لا يطبع محتوى السجلات ولا أسماء المستخدمين.

## قرار التقدم

لا تعتبر النتيجة صالحة للـshadow-read إلا إذا كان `clean: true`، وكان عدد النطاقات الغامضة صفرًا، وكانت اللقطة قد راجعت من ناحية الخصوصية. أي mismatch أو سجل زائد أو تكرار في نطاق المستخدم يحجب التقدم ولا يعالج تلقائيًا بالحذف.

> عدم وجود لقطة تشغيلية معقمة في بيئة المهمة يعني أن التحقق المنفذ حاليًا يثبت صحة runner والاختبارات فقط، ولا يمثل نتيجة parity لبيانات المشروع الفعلية.
