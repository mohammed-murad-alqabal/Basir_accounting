## الغرض

يحدد هذا المستند أي أصل يحسم كل نوع من أسئلة الحقيقة داخل Basir. لا توجد وثيقة واحدة تحسم كل شيء: **واقع التنفيذ** يحسم السلوك الحالي، و**المتطلبات المعتمدة** تحسم النية، و**الأدلة المؤرخة** تحسم الادعاء بالتحقق.

## هرمية السلطة

| المستوى | الأصل الحاكم | السؤال الذي يحسمه | أمثلة | لا يجوز استخدامه لإثبات |

## قاعدة الحسم عند التعارض

إذا تعارض README أو مواصفة أو تقرير مع الكود أو الاختبار أو الإعداد عند SHA محدد، يسجل الفرق كـ`DOC-DRIFT-*` أو `REQ-GAP-*`، ويعامل واقع التنفيذ بوصفه الحقيقة عن السلوك الحالي. إذا كان هذا الواقع لا يحقق النية المعتمدة، يفتح تغيير أو متطلب أو ADR؛ لا يعاد توصيف الكود أو الوثيقة بصورة صامتة.

> **حظر مطلق:** لا تستخدم كلمات `production ready` أو `compliant` أو `verified` أو `100%` لإثبات حالة حية ما لم تربط بـSHA وartifact دليل ومالك نطاق.

## دورة الوثيقة

| الحالة | المعنى | الانتقال المسموح |
|---|---|---|
| DRAFT | مسودة غير حاكمة. | إلى ACTIVE بعد تعيين owner والنطاق. |
| ACTIVE | وثيقة تشغيلية/قيد المراجعة. | إلى APPROVED أو SUPERSEDED أو ARCHIVED. |
| APPROVED | مصدر نية أو قرار معتمد. | إلى SUPERSEDED أو ARCHIVED فقط بقرار موثق. |
| SUPERSEDED | حل محلها أصل محدد. | إلى ARCHIVED بعد إصلاح المراجع. |
| ARCHIVED | تاريخ محفوظ غير حاكم. | لا تعديل للمحتوى إلا تصحيح metadata أو رابط. |

## قواعد التغيير

أي تغيير في المحاسبة أو الأمن أو الامتثال أو مخطط البيانات أو التكامل أو tokens الواجهة يجب أن يشير في PR إلى `REQ-*` و`ADR-*` إن لزم واختبارات ودليل CI. وتصبح هذه القاعدة آلية وفق خارطة التنفيذ بعد فترة advisory قصيرة.
