## الغرض

يسجل هذا القرار نتائج المراجعة الحالية ويمنع دمج أو حذف أعمال اعتمادًا على اسم الفرع أو عمره أو وجود ملفات مولّدة وحده. لا يحوّل هذا القرار أي ادعاء وظيفي أو تنظيمي إلى حقيقة مثبتة، ولا يستبدل موافقة مالك المستودع المطلوبة لأرشفة أو supersede وثيقة تاريخية.

## القرار المقترح بشأن المصادر المولّدة

تُعامل ملفات `*.g.dart` و`*.freezed.dart` وملفات build الناتجة عن `build_runner` بوصفها **artifacts مولّدة** وليست مصدر الحقيقة الافتراضي. مصدر الحقيقة هو كود المصدر والعقود والـworkflow الذي يعيد التوليد. يظل هذا القرار متسقًا مع `.gitignore` الحالي ومع أوامر `dart run build_runner build --delete-conflicting-outputs` الموجودة في CI.

لا يُدمج أي PR يضيف مجموعة كبيرة من المصادر المولّدة إلى `main` إلا إذا أرفق صاحب التغيير، في نفس PR، دليلًا على واحد من الاستثناءات التالية: متطلب نشر أو أداة لا تستطيع التوليد في بيئة الإصدار؛ عقد توافق موثق يثبت أن الملفات جزء من واجهة عامة؛ أو قرار معماري معتمد يحدد مالك الملفات، طريقة تحديثها، وفحص عدم الانحراف. نجاح فحوص syntax أو وجود الملفات وحده لا يثبت الاستثناء.

تُعاد PRs المتداخلة #43 و#49 و#83 و#127 و#52 إلى أصحابها لإثبات مصدر الحقيقة أو استخراج التغيير الفريد منها. لا يجوز دمجها كما هي، ولا حذفها قبل حفظ diff وموافقة مالك التغيير.

## القرار المقترح بشأن `SYNC_STATUS_REPORT.md`

يُصنف `SYNC_STATUS_REPORT.md` بوصفه **LEGACY-REFERENCE / ARCHIVE-CANDIDATE**، وليس مصدرًا حاليًا للحالة. السبب أن تاريخ التقرير وحالة SHA واسم المستودع وتعليمات المزامنة لا تطابق الحالة الفعلية الحالية في GitHub.

يُحظر استخدام أي نص في التقرير يوصي بوضع PAT أو secret داخل عنوان remote. الطريقة المعتمدة هي GitHub CLI أو credential helper أو آلية أسرار آمنة؛ لا تُسجل الرموز في shell history أو ملفات Git config أو logs. أُضيف تحذير واضح إلى مقدمة التقرير، مع إبقاء النص التاريخي محفوظًا وعدم نقله أو حذفه.

لا يتم نقل التقرير إلى `docs/archive/` أو حذفه أو اعتباره superseded نهائيًا إلا بعد فحص الروابط وتسمية المالك واعتماد قرار `ARCHIVE` أو `SUPERSEDE` مستقل. وحتى ذلك الحين، يجب أن يظهر التحذير التاريخي عند فتح الملف.

## ما لم يُحسم

هذا القرار لا يمنح اعتمادًا نهائيًا لسياسة المستودع، ولا يقرر إغلاق PRs أو حذف فروعها، ولا يثبت اكتمال الامتثال التنظيمي أو اتصال الإنتاج. يحتاج Repository Owner وEngineering Lead إلى اعتماد الحالة النهائية، وتحديد مالك generated sources، وتحديد مصير التقرير التاريخي.

## الإجراء التالي المشروط

بعد الاعتماد، يُحدّث `DOCUMENTATION_REGISTER.md` من `DRAFT` إلى الحالة التي يوافق عليها المالك، وتُفتح PRs صغيرة منفصلة لأي أرشفة أو نقل. تبقى جميع التغييرات قابلة للعكس، ويجب أن يحتوي كل قرار على SHA وPR ودليل فحص الروابط.
