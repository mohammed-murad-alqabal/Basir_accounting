### 🆕 إضافة وثيقة جديدة

#### الخطوة 1: تحديد النوع والمجلد

**اسأل نفسك:**

- ما نوع الوثيقة؟ (تقرير، دليل، مواصفة، ملخص جلسة)
- من الجمهور المستهدف؟ (مطورين، مديرين، مصممين، مختبرين)
- ما مستوى الأهمية؟ (أساسي، مهم، مرجعي)

**اختر المجلد المناسب:**

```bash
# للوثائق الاستراتيجية والأساسية
Core/

# للتقارير التقنية
reports/engineering/

# للتقارير الإدارية
reports/project-status/

# للأدلة العملية
guides/development/
guides/troubleshooting/

# لملخصات الجلسات
sessions/comprehensive/
sessions/specialized/
```

**قواعد التسمية:**


#### الخطوة 4: كتابة المحتوى

**نصائح للكتابة الفعالة:**

1. **ابدأ بالهدف الواضح**

   - ما الهدف من هذه الوثيقة؟
   - من سيستفيد منها؟
   - متى ستُستخدم؟

2. **استخدم لغة واضحة ومباشرة**

   - جمل قصيرة ومفهومة
   - تجنب المصطلحات المعقدة بدون شرح
   - استخدم أمثلة عملية

3. **نظم المحتوى منطقياً**

   - عناوين واضحة ومتدرجة
   - قوائم نقطية للمعلومات المتعددة
   - جداول للمقارنات والإحصائيات

4. **أضف عناصر بصرية**
   - رموز تعبيرية للتصنيف (📊 للإحصائيات، 🔧 للأدوات)
   - جداول للبيانات المنظمة
   - أمثلة كود مع تنسيق صحيح

#### الخطوة 5: المراجعة والتحسين

**قائمة التحقق قبل النشر:**

- [ ] العنوان واضح ووصفي
- [ ] المعلومات الأساسية مكتملة (تاريخ، مؤلف، حالة)
- [ ] المحتوى منظم ومنطقي
- [ ] الروابط تعمل بشكل صحيح
- [ ] التنسيق متسق مع باقي الوثائق
- [ ] لا توجد أخطاء إملائية أو نحوية
- [ ] الأمثلة واضحة وقابلة للتطبيق

## 🔄 تحديث وثيقة موجودة

### متى تحدث وثيقة؟

- **معلومات قديمة:** تغيرت التقنيات أو العمليات
- **معلومات ناقصة:** اكتشاف نقاط مهمة مفقودة
- **تحسين الوضوح:** جعل المحتوى أكثر فهماً
- **إضافة أمثلة:** توضيح النقاط بأمثلة عملية

### خطوات التحديث

1. **اقرأ الوثيقة كاملة** لفهم السياق
2. **حدد النقاط التي تحتاج تحديث** بوضوح
3. **احتفظ بنسخة احتياطية** (Git يحفظها تلقائياً)
4. **اجر التعديلات المطلوبة** مع الحفاظ على التنسيق
5. **حدث التاريخ** في رأس الوثيقة
6. **اختبر الروابط** للتأكد من عملها

## 🔗 إدارة الروابط

### أنواع الروابط

**الروابط الداخلية (مفضلة):**

```markdown
# من نفس المجلد

[اسم الوثيقة](#)

# من مجلد فرعي

[اسم الوثيقة](#)

# من مجلد أعلى

[اسم الوثيقة](.#)

# من مجلد آخر

[اسم الوثيقة](#)
```

**الروابط لأقسام داخلية:**

```markdown
[اسم القسم](#اسم-القسم-بالعربية)
[Section Name](#section-name-in-english)
```

**الروابط الخارجية:**

```markdown
[موقع خارجي](https://example.com)
```

### نصائح للروابط

1. **استخدم مسارات نسبية دائماً** للملفات الداخلية
2. **اختبر الروابط** باستخدام `./check_links.sh`
3. **استخدم أسماء وصفية** للروابط
4. **تجنب الروابط المكسورة** بالتحقق الدوري

````
## 🎯 أفضل الممارسات

### للمساهمين الجدد

1. **ابدأ صغيراً**
   - حدث وثيقة موجودة أولاً
   - أضف أمثلة أو توضيحات
   - اكتسب خبرة قبل إنشاء وثائق جديدة

2. **اتبع الأنماط الموجودة**
   - راجع الوثائق المشابهة
   - استخدم نفس التنسيق والأسلوب
   - حافظ على الاتساق

3. **اطلب المراجعة**
   - شارك عملك مع الفريق
   - اطلب ملاحظات وتحسينات
   - تعلم من التعليقات

### للمساهمين المتقدمين

1. **فكر في المستقبل**
   - اكتب وثائق قابلة للصيانة
   - استخدم قوالب قابلة لإعادة الاستخدام
   - خطط للتوسع والنمو

2. **حسن العمليات**
   - طور أدوات جديدة للصيانة
   - حسن الأدوات الموجودة
   - اقترح تحسينات على البنية

3. **علم الآخرين**
   - شارك خبرتك مع المساهمين الجدد
   - اكتب أدلة متقدمة
   - ساعد في مراجعة المساهمات
````
