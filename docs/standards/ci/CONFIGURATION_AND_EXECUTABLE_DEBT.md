# سياسة ومعالجة دين ملفات التكوين والتنفيذ

## نطاق الحزمة

تعالج هذه الحزمة الملفات المولّدة المتتبعة، وتوثّق الملفات التنفيذية التي لا يمكن اعتبارها مهملة اعتمادًا على البحث النصي وحده. لا تُحذف ملفات تشغيلية أو أدوات صيانة لمجرد عدم وجود مستدعٍ ساكن؛ فقد تكون نقاط دخول يدوية أو hooks أو ملفات تعتمد عليها GitHub Actions وبيئات المطورين.

## القرار المنفّذ

| المسار | القرار | السبب | الأثر |
|---|---|---|---|
| `scripts/.cache/compatibility/scan_cache.json` | DELETE من Git / IGNORE محليًا | ملف cache مولّد يعاد بناؤه تلقائيًا بواسطة `scripts/steering_compatibility_checker.py` داخل `.cache/compatibility`، وليس مصدر حقيقة أو إعداد runtime | تقليل الضوضاء ومنع تغيّر cache من تلويث commits؛ لا فقدان وظيفي لأن الأداة تنشئه عند الحاجة |
| `scripts/.cache/compatibility/` | IGNORE | مجلد مخرجات محلية مؤقتة | منع إعادة تتبع الملفات المولّدة مستقبلًا |

## ما لم يُحذف

تُبقى workflows الموجودة في `.github/workflows` لأنها تُكتشف وتُشغّل بمنصة GitHub، ولا يصح اعتبارها غير مستخدمة من خلال مراجع المستودع النصية. كما تُبقى سكربتات `rust_builder/cargokit` لأنها نقاط دخول للبناء الأصلي، وتُبقى hooks وملفات `scripts/maintenance` والأدوات الموجودة تحت `.kiro` إلى حين وجود دليل تشغيل/بديل واضح وموافقة منفصلة على الأرشفة أو الحذف.

## عناصر تحتاج تحقيقًا لاحقًا

توجد مجموعات متقاربة وظيفيًا بين `.kiro/scripts/testing/` و`scripts/` و`tools/kiro_optimizers/flutter/`، من بينها فحوص الجودة والاختبارات وتحديث الاعتماديات. تصنيفها الحالي **INVESTIGATE / REORGANIZE** وليس DELETE؛ يلزم تشغيلها أو مراجعة نقطة دخول موثقة قبل دمجها في أداة واحدة. كما ينبغي تقييم ملفات `scripts/archive/` وفق سياسة احتفاظ زمنية، دون حذف تلقائي.

## معيار قبول الحزمة

يجب أن ينجح `git diff --check`، وألا تظهر ملفات cache المتتبعة، وأن يظل `scripts/steering_compatibility_checker.py` قادرًا على إنشاء cache محليًا عند تشغيله. لا تتضمن الحزمة أي إعادة كتابة للتاريخ أو تعديلًا في إعدادات GitHub أو حماية الفروع.
