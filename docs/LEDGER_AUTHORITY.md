# سلطة دفتر الأستاذ ومسار الترحيل

## الحالة الحالية

حتى اكتمال ترحيل معماري مُثبت ومختبَر، يكون **مستودع القيود المحلي `AccountingRepository` المدعوم بـ Isar هو مصدر الحقيقة التشغيلي الوحيد لدفتر الأستاذ في تطبيق Flutter**. لا يجوز التعامل مع النماذج أو مخططات قاعدة البيانات في محرك Rust كمسار كتابة ثانٍ أو مصدر حقيقة موازٍ داخل التطبيق الحالي.

> وجود كود محرك Rust أو مخططاته لا يثبت وحده أنه مدمج في مسار الإنتاج. لا تُنشأ القيود من واجهة Rust ولا تُكرر إليها في الخلفية ما لم يُنفذ ترحيل صريح وتُثبت ذريته واختباراته.

## مسار الكتابة المعتمد

| الخطوة | المكوّن المسؤول | الضمان المطلوب |
|---|---|---|
| إنشاء مسودة | `AccountingService.saveJournalEntryDraft` | القيد متوازن، سطران على الأقل، ولا يؤثر في الأرصدة |
| الترحيل النهائي | `AccountingService.postJournalEntry` | فترة مفتوحة، عدم تكرار الهوية أو المرجع، إجماع إلزامي، ثم حفظ ذري |
| التخزين | `AccountingRepository.addJournalEntry` | لا تعديل لقيد مرحّل؛ يسمح فقط بتعديل المسودة أو انتقالها المنضبط إلى مرحّلة |
| العكس | `AccountingService.reverseJournalEntry` | قيد عكسي جديد عبر بوابة الترحيل؛ لا حذف ولا تعديل للأصل |
| التشخيص | `LedgerIntegrityService.verifyLedger` | يكتشف الشذوذ فقط؛ لا ينشئ قيود تصحيح تلقائية |

## حواجز ممنوعة

لا تُقبل أي إضافة توفر أيًا مما يلي:

- معامل عام أو مسار واجهة يتجاوز الإجماع أو فحص الفترة أو عدم التكرار.
- تصحيح تلقائي ينشئ أثرًا ماليًا أو حسابًا معلقًا دون إعداد ومراجعة واعتماد.
- كتابة مباشرة إلى مخزن القيود من واجهة العرض أو خدمة التقارير أو المحاكاة.
- مزامنة ثنائية الاتجاه مع محرك Rust أو خدمة خارجية قبل تحديد مالك البيانات والمعاملات وتغطية سيناريوهات الفشل والاسترداد.

## خطة الترحيل إلى Rust، إن تقررت

أي نقل للسلطة إلى Rust يتطلب قرارًا معماريًا جديدًا وتنفيذًا مستقلًا يتضمن: واجهة أوامر واحدة، معرفات idempotency، معاملات تغطي القيد والحركات والوثيقة المصدر، سجل تدقيق غير قابل للتعديل، ترحيل بيانات مدروس، اختبارات توافق Flutter/FFI/Rust، وخطة استرجاع. إلى حين اجتياز هذه البوابات، يظل Isar هو المسار التشغيلي المعتمد.

## قرار الإصدار

يُحظر الإصدار الإنتاجي إذا وُجد مسار كتابة ثانٍ أو تجاوز لأي حاجز في هذه الوثيقة. تتحقق بوابة CI من التحليل والاختبارات؛ ويبقى التحقق التشغيلي الكامل وقرار الإطلاق خاضعين لتشغيل أدوات Flutter وRust الفعلية ونجاح اختبارات القبول.
