# دليل مصالحة دفتر الأستاذ السلطوي

> **لا تعالج المصالحة التعارضات تلقائيًا.** تعمل الأداة في وضع قراءة فقط، وتقرر أن PostgreSQL هي الحقيقة المنشورة دائمًا.

## متى تُشغّل المصالحة

شغّلها بعد انقطاع طويل، أو إعادة تثبيت عميل، أو قبل إطلاق ترحيل السلطة، أو عند تنبيه `ledger_health_check.sql`. لا تستخدمها بديلًا عن اختبار فترة مالية أو موافقة محاسب مخول.

## المدخلات والمخرجات

صدّر قائمة cache Isar وقائمة القيود المنشورة من PostgreSQL بصيغة JSON. يقبل كل ملف مصفوفة entries أو كائنًا يحوي `entries`. يجب أن تحمل نسخة Isar معرف `authoritativeEntryId` وhash إن كانت قيدًا منشورًا؛ وتحمل PostgreSQL `id` وhash.

```bash
python3 scripts/reconcile_ledger.py \
  --isar /secure-export/isar-journal.json \
  --postgres /secure-export/postgres-journal.json \
  --output /secure-output/ledger-reconciliation.json
```

| رمز الخروج | الدلالة | الإجراء |
|---:|---|---|
| `0` | لا توجد تعارضات | احفظ التقرير ضمن أدلة التشغيل. |
| `1` | توجد تعارضات أو قيود محلية غير مستلمة | أوقف أي كتابة محلية، واعمل وفق الجدول التالي. |
| `2` | ملف دليل غير صالح أو غير قابل للقراءة | صحح التصدير؛ لا تستنتج أي حكم محاسبي. |

## تصنيف النتائج

| التصنيف | المعنى | الإجراء المسموح |
|---|---|---|
| `match` | hash ومرجع cache متسقان | لا إجراء. |
| `missing_local_cache` | القيد موجود في PostgreSQL ولا cache محلية له | حدّث cache من API القراءة الخادمي. |
| `conflict` مع hash مختلف | Isar لا يطابق السجل الخادمي | اعزل cache المحلي، وأعد قراءته من PostgreSQL؛ لا تنسخ Isar للخادم. |
| `conflict` لقيد Isar posted بلا receipt | يوجد نشر محلي تاريخي غير موثق خادميًا | اعزل السجل، وافتح حالة محاسبية؛ لا تنشئ نشرًا تلقائيًا. |
| `conflict` لمعرف خادمي مفقود | cache يشير إلى receipt غير موجود | راجع الحذف أو بيئة التصدير، ثم حدّث cache من المصدر السلطوي. |

## تسلسل الاستجابة

1. احفظ exports الأصلية والتقرير الناتج مع طابع زمني ومعرف بيئة.
2. شغّل `psql -f scripts/ledger_health_check.sql` على قاعدة القراءة أو نسخة مماثلة؛ أي صف ذي violations غير صفرية يمنع الإطلاق.
3. إذا كان التقرير يحوي `conflict`، أوقف flush لهذا العميل واستخدم `source_of_truth: postgres` للحكم.
4. اجعل API القراءة يعيد القيد الخادمي المكتمل، ثم استبدل cache المحلي ضمن معاملة Isar منفصلة. لا تستدعِ `addJournalEntry` لحالة `Posted`.
5. إذا لم يوجد القيد في PostgreSQL لكن له أثر أعمال، أنشئ **أمرًا جديدًا** بموافقة محاسب. لا تعيد استخدام `operation_id` بحمولة مختلفة.
6. أعد تشغيل المصالحة وفحص الصحة واحفظ الأدلة قبل استئناف المزامنة.

## ضوابط منع الضرر

* لا تحذف أو تعدل journal entry منشورًا لكسب التطابق.
* لا تُشغّل أداة المصالحة على بيانات اعتماد إنتاجية ذات صلاحية كتابة؛ فهي لا تحتاج إليها.
* عالج رصيدًا خاطئًا بقيد تسوية/عكس خاضع للتفويض والتدقيق.
* لا تعتبر خروج outbox أو انقطاع الشبكة إثباتًا لنشر؛ receipt الخادم فقط هو الإثبات.
