# نتيجة تحقق حزمة Drift المعزولة

**الحالة:** تحقق محلي مكتمل جزئيًا؛ لا commit أو push أو تعديل لطلب السحب من هذه الجولة.

## القرار المنفذ

أظهرت محاولتا حل التبعيات أن `drift_dev` لا يمكنه التعايش في root package مع `isar_generator 3.1.0+1`. عُزل Drift لذلك في الحزمة الداخلية `packages/basir_drift_storage`، بينما يحتفظ root بتبعيات Isar ومولداته. يعتمد root عليها كـpath dependency وقت التشغيل فقط.

| البوابة | النتيجة |
|---|---|
| Flutter/Dart | Flutter 3.35.5 / Dart 3.9.2 جُهزت محليًا |
| حزمة Drift: `pub get` | ناجح |
| حزمة Drift: `build_runner` | ناجح؛ كتب 10 مخرجات مولدة |
| حزمة Drift: الاختبارات | ناجح؛ 4 اختبارات |
| root: `pub get` | ناجح مع path dependency |
| root: `build_runner` | ناجح؛ مولد Isar ما زال يعمل |
| root: اختبار مكيّف الباركود | ناجح؛ 4 اختبارات |
| التحليل المستهدف | 0 أخطاء، 0 تحذيرات، 9 ملاحظات lint أسلوبية غير حاجبة |
| بناء Web | ما زال يفشل بسبب 90 ثابت schema Isar كبيرًا غير قابل للتمثيل في JavaScript؛ لا تظهر أي إشارة إلى Drift في سجل الفشل |

## مجموعة التبعيات المقفلة

تستخدم الحزمة `drift 2.31.0`، و`drift_dev 2.31.0`، و`drift_flutter ^0.2.7`. هذه المجموعة تتوافق مع Dart 3.9، وSQLite 2.x، وواجهة Web/WASM التي تحتاج `sqlite3.wasm` و`drift_worker.dart.js` لاحقًا. تعمدنا عدم إضافة أصول WASM قبل معالجة فشل Isar في بناء Web.

## ملاحظات غير حاجبة

ملف `.env` غائب في بيئة التحقق، لذلك أنشئ placeholder فارغ محلي ومُتجاهل فقط لأجل Flutter asset bundle؛ لم يُتبع ولم يحتو أي سر. ثُبتت مكتبة SQLite للنظام محليًا لتشغيل اختبارات Drift الأصلية؛ ليست ضمن تغييرات المستودع.

## التغيير المتوقع في الجولة التالية

ستحل الحزمة الداخلية محل ملف Drift في root، وتُحدَّث ملفات plugin registrant اللازمة لـ`sqlite3_flutter_libs`، ويُحدَّث lockfile. لن يتغير أي Riverpod provider، وسيبقى Isar التنفيذ الفعال. يلزم commit منفصل وموافقة push منفصلة إذا اعتمدت النتيجة.
