# تقرير فجوات UI/UX وتنفيذ الأساس المتجاوب في بصير

**التاريخ:** 22 أغسطس 2026 — تحديث متابعة

## الخلاصة التنفيذية

أظهر فحص مخطط UI/UX التنفيذي، وملاحظات الفحص البصري، ومواءمة المخطط مع المستودع أن المشروع يمتلك طبقة تصميم قوية نسبيًا: رموز ألوان ومسافات، ثيم Material 3، دعم RTL والتوطين، مكونات مشتركة، وشاشات تشغيلية متعددة. إلا أن نقطة الدخول الرئيسية `/dashboard` كانت تستخدم `BasirAppShell` الذي يعرض شاشات بديلة ثابتة، بينما كانت عناصر التنقل في الشريط الجانبي والشريط السفلي غير موصولة بأي حالة تنقل، وكان البحث والإشعارات في الشريط العلوي يعرضان واجهة غير تفاعلية.

تم تنفيذ إصلاح تأسيسي عالي الأثر داخل فرع `manus/basir-ui-ux-foundation`: أصبح الهيكل المتجاوب يعرض الوحدات الفعلية، ويشارك فهرس الوحدة بين تخطيط المكتب والهاتف، ويستجيب لاختيار بنود التنقل، ويتيح طي الشريط الجانبي، ويحوّل البحث والإشعارات من عناصر ميتة إلى تفاعلات مرئية آمنة.

## الفجوات التي عولجت

| الفجوة | الأثر قبل التنفيذ | المعالجة المنفذة |
| --- | --- | --- |
| شاشات بديلة داخل `BasirAppShell` | فتح `/dashboard` لا يعرض الوحدات الفعلية | استبدال القائمة البديلة بقائمة الشاشات الإنتاجية الثمانية: الرئيسية، الفواتير، الموردون، العملاء، المخزون، الأصول، التقارير، والإعدادات |
| عدم وجود حالة تنقل مشتركة | لا يمكن الانتقال فعليًا من الشريط الجانبي أو السفلي | تحويل الهيكل إلى `ConsumerStatefulWidget` مع فهرس واحد واستخدام `IndexedStack` في التخطيطين |
| بنود الشريط الجانبي بلا إجراء | النقر لا يغير الوحدة النشطة | إضافة `onItemSelected` وربطه بفهرس الهيكل |
| زر طي الشريط الجانبي بلا إجراء | لا يمكن التحكم بكثافة مساحة العمل | ربط الزر بـ `sidebarCollapsedProvider` مع الحفاظ على إعلان الوصولية |
| شريط الهاتف السفلي يعرض أيقونات فقط ونقراته ميتة | ضعف قابلية اكتشاف الوحدة النشطة وعدم إمكانية التنقل | إضافة التسميات، الحالة الدلالية، ون callback فعلي للنقر، مع دعم التقارير كبند ثامن |
| البحث والإشعارات غير تفاعليين | واجهة توحي بوجود وظائف غير منفذة | ربط الشريط بـ Omnibar حقيقي لنتائج الفواتير والعملاء والأصناف والأوامر، مع تغذية راجعة مرئية للإشعارات |

## الملفات المعدلة

| الملف | التغيير |
| --- | --- |
| `lib/shared/widgets/app_shell.dart` | ربط الشاشات الفعلية، إدارة الفهرس، وتفعيل التنقل المتجاوب |
| `lib/shared/widgets/basir_sidebar.dart` | إضافة callback للتنقل وتفعيل طي الشريط الجانبي |
| `lib/shared/widgets/basir_topbar.dart` | تفعيل البحث والإشعارات وربط الشريط بـ Omnibar الموجود |
| `lib/features/navigation/presentation/widgets/omnibar.dart` | تمرير ProviderContainer إلى الحوار حتى يعمل Omnibar عند فتحه من root navigator دون فقدان Riverpod scope |

## التحقق

تم تنفيذ `git diff --check` بنجاح، كما نجح محليًا `flutter analyze lib/shared/widgets/app_shell.dart` باستخدام Flutter 3.35.5. أضيفت اختبارات تفاعل لاختيار الوحدة وفتح Omnibar. بعد إصلاح فقدان ProviderScope وإزالة عملية `toInt` غير اللازمة، نجح تشغيل Flutter CI الكامل على commit `d2670c13`، بما في ذلك التنسيق، التحليل، فحص الأمان، اختبارات الوحدة، وفحص التغطية. بقي Pull Request مفتوحًا ومسودة للمراجعة النهائية، مع وجود بعض الفحوص غير المتعلقة مباشرة بالكود ما زالت قيد المعالجة أو تتبع سياسات المستودع.

## الأولويات التالية

العمل المنفذ هو طبقة الأساس وليس اكتمال كل المخطط التنفيذي. أصبح البحث الآن يستخدم Omnibar الموجود في المشروع، ويصنف نتائج الفواتير والعملاء والأصناف والأوامر ويربطها بمسارات التفاصيل؛ وتبقى الأولوية التالية تحسين تعريب Omnibar وإكمال تغطية التقارير والحسابات والموردين داخل فهرس البحث. بعد ذلك ينبغي ربط شرائح المؤسسة والفرع والفترة ببيانات المستخدم وصلاحياته، ثم إضافة `PageHeader` موحد ومسار تنقل داخل الشاشات، وتدقيق حالات الوثائق والأثر المالي، وتحسين تجربة الهاتف لتكون قائمة الوحدات عامة وشريط الإجراءات سفليًا سياقيًا بدل تكرار التنقل العام في كل شاشة.

كما ينبغي استكمال معالجات الاستيراد والتغيير الجماعي والجرد كمعالجات متعددة الخطوات، وربط `AuditTimeline` و`StatusToast` بسجل المجال الفعلي، ثم إضافة اختبارات تفاعل تغطي اختيار الوحدة وطي الشريط والبحث عبر أبعاد سطح المكتب واللوحي والهاتف.
